# Acquisition-aware IMU contract — tranche 5

Status: local development snapshot, September 6, 2026. This extends the tranche 4
source archive. It is not a published release or a hardware validation.

## Boundary and compatibility

`ImuModel`, `ImuOutput`, the trajectory API, direct-rate/increment API, and their
existing configuration meanings are unchanged. The new `AcquiredImuModel`
implements `AcquiredImuModelProtocol`, not `ImuModelProtocol`. Its output is
`AcquiredImuSample`: six instrument-channel rates, reported interval bounds,
observed ambient temperature, a sample index, and six validity flags.

This separation is deliberate. A causal digital filter combines historical
instrument readings. Those readings cannot silently be relabeled as a single
instantaneous body-frame vector or an SO(3) preintegrated increment. The sample
contains no physical-time or die-temperature oracle. Simulation-side snapshots
retain that information for replay and evaluation only.

The physical interval is supplied explicitly to the new method. Uniform,
contiguous sampling is required. A sampling-clock error that changes the
physical acquisition schedule is not the same as an error in its reported time.
This tranche implements the latter only.

## Implemented signal path

```text
externally generated ideal force and angular rate over a physical interval
    + observed, interval-held ambient temperature
        -> exact one-node die-temperature interval
        -> existing ImuModel at the interval-mean die temperature
           (intrinsics, drift, white noise, clipping, quantization, scaling)
        -> causal digital FIR, then integer-sample channel readout delays
        -> indicated SI rates and erroneous reported timestamps
```

The digital filter is downstream of the existing electronics. It filters both
signal and the noise already generated by the core. It is not an analog
anti-aliasing filter and cannot undo aliasing that happened before sampling.
No additional white noise is added merely because filtering reduces the
sample-to-sample scatter.

The accelerometer and gyro triads may use different FIR kernels. Each of the six
channels may have a different integer-sample readout delay. These delays model
readout history/skew, not fractional physical sampling-aperture offsets.

## FIR law and state

For instrument channel j, with h ordered from current to oldest sample:

```text
y_j[k] = sum_l h_j[l] x_j[k - delay_j - l]
H_j(f) = sum_l h_j[l] exp(-i 2 pi f dt (delay_j + l))
```

Each configured kernel has finite coefficients and unit DC gain. Signed FIR
coefficients are allowed. Zero-DC/high-pass filters are rejected by this version
because they remove the stationary reference needed for gyrocompassing.

The filter uses one history across every pose or rotation in a run. It does not
reset at region boundaries. Startup values with incomplete history are marked
invalid per channel; numerical zero-padding during startup is not presented as
valid sensor evidence. Consumers must honor these flags. After reset, history
and the validity count restart explicitly.

The frequency-response helper is digital and excludes the external ideal-input
aperture and clock errors. A scalar phase correction is appropriate only for the
restricted matched-horizontal-filter, steady-harmonic carousel experiment. A
full inverse filter, cross-axis deconvolution, or arbitrary dynamic compensation
is not implemented here.

## Thermal law

The temperature node uses a held ambient input Ta:

```text
dTd/dt = (Ta - Td) / tau
Td(end) = Ta + (Td(start) - Ta) exp(-dt/tau)
Td(mean) = Ta + (Td(start) - Ta) (tau/dt) (1 - exp(-dt/tau))
```

The implementation uses `expm1` and a small-argument series. A zero time constant
is an explicit bypass. The endpoint becomes the next interval's initial state.
The sensor-visible temperature remains Ta; it is not replaced by hidden die
truth. The replay snapshot includes Td separately.

Evaluating the core at Td(mean) is exact for the linear deterministic thermal
terms with constant ideal rates over the interval. It is not generally exact
for temperature-dependent noise variance, clipping, or nonlinear within-sample
interactions. Such combinations require a time-step refinement study. This is a
one-node surrogate, not a multi-die thermal network, hysteresis, self-heating,
or a measured thermometer transfer function.

For a constant ambient step, an initial absolute difference D reaches tolerance
epsilon after `tau * log(D/epsilon)` when D exceeds epsilon. The settling helper
returns zero when the tolerance is already met.

## Clock law

```text
tag(t, k) = epoch + offset + (t - epoch) (1 + ppm * 1e-6) + jitter[k]
```

Jitter is uniform on the configured symmetric bound and deterministic from its
own seed and boundary index. It does not consume the sensor RNG. Adjacent
reported intervals reuse the same boundary value; interval errors therefore do
not behave as independent differences. No sorting or clamping conceals a time
reversal. Configuration rejects jitter envelopes that can exceed half the
reported nominal period. Runtime also rejects nonrepresentable timestamp steps;
local epochs are recommended.

Only the tags change. The generated rates and the core's physical dt do not.
A downstream consumer integrating rates with a clock that runs 100 ppm fast
will consequently obtain a 100 ppm integrated-angle gain error in the constant
rate example. The sensor's own physical interval is not silently rescaled.

## Exact white-noise mean covariance

Let Q be the covariance of independent prefilter rate samples. It is not a
noise-density matrix. For N retained samples following complete filter warm-up,
convolve each effective channel kernel with an N-sample averaging box to obtain
weights w_j. Then:

```text
Cov(mean_y)[i,j] = Q[i,j] sum_k w_i[k] w_j[k]
```

This handles unequal kernels, channel delays, and cross-channel covariance.
It does not include colored bias, uncertainty in fitted kernels, temperature
uncertainty, clock error, or calibration uncertainty. Those must enter a separate
model rather than being counted again as independent measurement noise.

For a unit-gain low-pass filter and a long record, the mean uncertainty is close
to that of the original record; filtering reduces scatter but creates serial
correlation. Counting every smoothed output as a new independent observation can
severely understate the uncertainty.

## Identification and identifiability

`fit_readout_kernel` accepts only synchronized known reference rates and measured
rates. It fits an effective FIR plus offset for each channel, rejects insufficient
rank or poor conditioning, and reports residual RMS. A held-out prediction route
uses the fitted kernel, not the injected configuration.

A pure delay and leading zero coefficients have the same effective response.
They are not separately identified. Clock offset and filter phase are also
confounded without independent timing/reference information. Intrinsic gain,
axis transforms, unknown motion, and temperature dynamics are not jointly fitted
by this method. Broadband sample-level excitation is a numerical component test,
not a claim that an arbitrary sequence is realizable by a bandwidth-limited rig.

## Confidence and stopping

The new planner is a separate static, level, near-north illustration. It uses
known prefilter IID Gaussian noise, optional independent Gaussian calibration
heading uncertainty, and a supplied bound B on remaining systematic heading
error. Its half-width is `z * sigma_random + B`. B is not treated as a zero-mean
random sample that can be averaged away. An unknown bound returns
`missing_systematic_bound`, not a successful target decision.

A finite predeclared sequence of m checks may use the Bonferroni-adjusted value
`z = NormalDist().inv_cdf(1 - (1-confidence)/(2*m))`. This protects a fixed finite
set of model-valid marginal intervals without requiring independent checks.
It is not an anytime-valid confidence sequence, and it does not make estimated
or misspecified noise laws valid. Existing unadjusted prefix results remain
descriptive fixed-prefix evidence, not an optional-stopping guarantee.

The static planner's covariance is not the carousel estimator's covariance. The
0.87-degree and 0.03-degree systematic bounds in its campaign are illustrative
user assumptions; the fitted phase experiment does not certify either bound.

## Persistence and dependencies

All acquisition configurations and replay checkpoints have schema version 1.
Checkpoints include the core stochastic state, filter history, die temperature,
clock counter and physical/reported boundaries. Restore validates the complete
state before replacing it. Existing core checkpoint files are unchanged.

The runtime adds no dependencies beyond the existing NumPy/Pydantic stack. The
playground remains source-only experimental infrastructure, outside the runtime
wheel. ROS, Gazebo, geodesy services, device drivers and visualization remain
external. Earth rotation still comes from the external local reference generator.
